## 先建立直觉

把 LLM 想成一个 **「超级自动补全」**：给它一串文字，它预测「下一个最可能出现的字/词」。它的全部能力，都来自在海量文本上反复练习「看前文、猜后文」。

- **它不是在背答案**，而是在学「人类语言/知识的概率分布」；
- **它没有真正的理解**，但足够大的模型 + 足够多的数据，会涌现出推理、翻译、写代码等能力；
- **「训练」的本质** = 用梯度下降，把「猜得准」这件事，刻进几十亿个参数里。

## 它解决什么问题

为什么大家都在训自己的 LLM？三类动机：

1. **数据隐私 / 合规**：金融、医疗、政企数据不能出内网，必须私有化训练。
2. **领域专精**：通用模型不懂你的业务黑话，用领域语料继续训能显著提升效果。
3. **成本与可控**：长期高频调用，自训 + 私有部署比调 API 更省钱、可定制。

一条完整的训练链路（也是本教程的章节地图）：

```mermaid
flowchart LR
    A[原始文本] --> B[数据清洗/去重]
    B --> C[分词 Tokenizer]
    C --> D[预训练 Pretrain]
    D --> E[基座模型 Base]
    E --> F[SFT 微调]
    F --> G[对齐 RLHF/DPO]
    G --> H[部署 Serving]
```

| 阶段 | 输入 → 输出 | 数据量级 | 是否必须 |
|------|-------------|----------|----------|
| 预训练 | 原始文本 → 基座模型 | TB 级 token | ✅ 核心 |
| SFT | 对话/指令 → 助手模型 | 万~十万条 | ✅ 通常要 |
| 对齐 | 偏好数据 → 更安全模型 | 千~万条 | ⚠️ 看场景 |

> 注意：**微调（SFT）不是从零训**。如果你只是想「让现成模型适配自己的业务」，往往只需 SFT 甚至 LoRA，根本不用走预训练。本教程讲「从零」，是为了让你理解全貌；实际项目按需取用。

## 核心概念

### 1. 参数规模与硬件的对应关系

| 规模 | 参数量 | 训练显存（bf16，粗估） | 典型硬件 | 适合阶段 |
|------|--------|------------------------|----------|----------|
| Nano | 1M–100M | < 8 GB | 单张 3060/4060 | 本教程 demo |
| 小模型 | 0.5B–1B | 16–40 GB | 单张 24G（3090/4090） | 教学/实验 |
| 中模型 | 7B–13B | 80–320 GB | 1–4×A100 80G | 可落地 |
| 大模型 | 70B+ | 多 TB | 数十张 H100 集群 | 工业级 |

> 经验公式：训练时单卡显存 ≈ **参数量 × 18~20 字节**（含优化器状态 Adam 的 12B + 梯度 2B + 参数 2B + 激活）。7B 全参训练 ≈ 7×18 ≈ 126 GB，所以单卡 80G 训不了 7B 全参，要用 ZeRO-3 / 流水线并行。

### 2. 本教程默认工具栈

```bash
# 最小可跑环境（CUDA 12.1 示例，请按本机 CUDA 调整）
pip install torch==2.3.1 --index-url https://download.pytorch.org/whl/cu121
pip install transformers==4.44.0 tokenizers==0.19.1 datasets==2.21.0 \
            accelerate==0.33.0 deepspeed==0.14.4 peft==0.12.0 trl==0.9.6
```

| 工具 | 角色 |
|------|------|
| `torch` | 张量与自动求导 |
| `transformers` | 模型/分词器封装、推理 |
| `tokenizers` | 高性能 BPE 训练（Rust 后端） |
| `datasets` | 大规模语料流式加载与清洗 |
| `accelerate` / `deepspeed` | 单卡→多卡分布式 |
| `peft` / `trl` | LoRA 微调 / SFT·RLHF·DPO 训练 |

## 常见坑

1. **CUDA 版本不匹配**：`pip install torch` 默认装 CPU 版，必须用 `--index-url` 指定 cu 版本，且要与本地驱动匹配（`nvidia-smi` 看最高支持版本）。
2. **显存爆炸才想分布式**：提前规划。demo 用 nano 模型验证流程，再放大；别一上来就训 7B。
3. **把「微调」当「预训练」**：拿几十条数据全参训大模型，只会灾难性遗忘。小数据请走 LoRA + 低学习率。
4. **忽视随机种子**：不复现 seed，loss 忽高忽低无从 debug。训练脚本开头务必固定 `seed`。

## 小结

- LLM = 超大规模「下一 token 预测」；训练 = 把这种能力刻进参数；
- 完整链路：数据 → 分词 → 预训练 → SFT → 对齐 → 部署；
- 硬件按规模递增，本教程**所有代码先给单卡小模型版，再讲放大**；
