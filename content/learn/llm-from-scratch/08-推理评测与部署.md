## 先建立直觉

模型训好 ≠ 能用。最后一步是把它变成「用户问一句、秒回一句」的服务。

- **生成** = 自回归：每次吐一个 token，把新 token 拼回去继续吐，直到遇到结束符；
- **采样** = 怎么选下一个 token（别总选最可能的，否则又呆又重复）；
- **量化** = 把 fp16 权重压成 int4/int8，显存砍半甚至砍到 1/4，让小卡也能跑大模型；
- **部署** = 用 vLLM 这类引擎，批量并发、KV Cache 复用，把吞吐拉满。

## 它解决什么问题

1. **显存放不下**：7B fp16 约 14GB，量化到 4bit 仅 ~4GB，单张 4060 就能跑。
2. **延迟高、并发低**：朴素 `generate` 一次只服务一个请求；vLLM 用 PagedAttention 把吞吐提升数倍。
3. **不知道训得咋样**：需要客观基准（MMLU 等）量化能力，而非「感觉还行」。

## 核心概念

### 1. 自回归生成 + 采样策略

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

tok = AutoTokenizer.from_pretrained("dpo-llm-final")
model = AutoModelForCausalLM.from_pretrained("dpo-llm-final").cuda()

prompt = "<|user|>\n用一句话解释梯度下降<|endoftext|>\n<|assistant|>\n"
inputs = tok(prompt, return_tensors="pt").to("cuda")

out = model.generate(
    **inputs,
    max_new_tokens=128,
    do_sample=True,
    temperature=0.7,      # 越高越随机/有创意
    top_p=0.9,            # 核采样：只从累计概率 90% 的词里选
    top_k=50,             # 再限制最多 50 个候选
    repetition_penalty=1.1,
)
print(tok.decode(out[0], skip_special_tokens=True))
```

| 参数 | 作用 | 取值建议 |
|------|------|----------|
| `temperature` | 平滑概率分布 | 0=贪心确定性；0.7~1.0 通用；>1.2 发散 |
| `top_p` | 核采样截断 | 0.9 常用 |
| `top_k` | 候选上限 | 40~50 |
| `repetition_penalty` | 抑制重复 | 1.1 左右 |

### 2. 量化：显存压缩三件套

| 方法 | 原理 | 工具 | 典型压缩 |
|------|------|------|----------|
| **GPTQ** | 训练后量化，最小化重建误差 | `auto-gptq` / `transformers` | 4bit |
| **AWQ** | 保护「重要权重」再量化 | `autoawq` | 4bit，常优于 GPTQ |
| **GGUF** | 跨平台 CPU/GPU 格式 | `llama.cpp` | 2~8bit，笔记本可跑 |

AWQ 示例：

```python
from awq import AutoAWQForCausalLM
model = AutoAWQForCausalLM.from_pretrained("dpo-llm-final", device_map="auto")
model.quantize(tokenizer, quant_config={"w_bit":4, "q_group_size":128})
model.save_quantized("dpo-llm-awq-4bit")
```

> 量化会掉一点精度，但 4bit 通常只降 1~2 个点，换来的显存/速度收益巨大。小卡部署首选。

### 3. 高吞吐部署：vLLM

```bash
pip install vllm
```

```python
from vllm import LLM, SamplingParams
llm = LLM(model="dpo-llm-awq-4bit", gpu_memory_utilization=0.9,
          tensor_parallel_size=1)        # 多卡设 >1
params = SamplingParams(temperature=0.7, top_p=0.9, max_tokens=256)
outputs = llm.generate(["解释一下注意力机制", "写个快速排序"], params)
for o in outputs:
    print(o.outputs[0].text)
```

启动 OpenAI 兼容服务（前端/业务直接调）：

```bash
python -m vllm.entrypoints.openai.api_server \
    --model dpo-llm-awq-4bit --served-model-name my-llm --port 8000
# 之后用 openai 客户端访问：POST /v1/chat/completions
```

> vLLM 的 **PagedAttention** 把 KV Cache 像虚拟内存一样分页管理，显存利用率和并发远超朴素部署。

### 4. 评测：用基准说话

| 基准 | 测什么 |
|------|--------|
| **MMLU** | 57 学科多选题（知识广度） |
| **GSM8K** | 小学数学应用题（推理） |
| **HumanEval** | 代码生成（pass@1） |
| **MT-Bench** | 多轮对话质量（LLM 打分） |

用 `lm-eval-harness` 一行跑：

```bash
pip install lm-eval
lm_eval --model hf --model_args pretrained=dpo-llm-final --tasks mmlu,gsm8k --device cuda:0
```

> 评测要**对比基线**（预训练后 / SFT 后 / DPO 后），看每一步是否真的在涨，防止「越对齐越笨」。

## 常见坑

1. **推理模板和训练不一致**：忘了拼 `<|user|>`/`<bos>`，输出全是乱码或复述。模板必须和 SFT/对齐阶段一致。
2. **temperature=0 还嫌呆**：其实贪心本就确定；想要多样就调到 0.7~0.9，但别超过 1.3 否则胡言。
3. **量化后没测精度**：4bit 有时对某些任务掉得多，量化后务必跑一遍关键基准。
4. **直接 `model.generate` 上生产**：无并发、显存浪费，QPS 极低。生产用 vLLM / TGI。
5. **只看 loss 不看基准**：训练 loss 低 ≠ 能力强，必须跑 MMLU 等客观评测。

## 小结

- 生成 = 自回归 + 采样（temperature/top-p 控随机度）；
- 量化（GPTQ/AWQ/GGUF）把大模型压进小卡，4bit 几乎无损；
- 生产部署用 **vLLM**（PagedAttention，高吞吐、OpenAI 兼容）；
- 用 MMLU/GSM8K/HumanEval 客观评测，对比各阶段是否真在进步；
- 到这一章，你已经跑通「数据 → 分词 → 架构 → 预训练 → SFT → 对齐 → 部署」全链路。恭喜，你从零训出了一个能用的 LLM。
