## 1. 协议定位

| 项目 | 信息 |
|------|------|
| 所属层 | 传输层 |
| 英文全称 | User Datagram Protocol |
| 主要 RFC | **RFC 768**（STD 6，1980） |
| 端口 | 用端口号标识会话（IP 协议号 17） |
| 封装于 | IP（协议号 17） |
| 典型应用 | DNS、DHCP、SNMP、TFTP、视频/语音、QUIC(HTTP/3)、游戏 |

## 2. 一句话理解

**UDP 是"写好地址就丢出去的信封"**：不握手、不确认、不重传，发出去就不管是否到达。它只做两件事——**加端口号**把数据交给正确应用、**保留消息边界**让接收方一次收一整条。低开销、低延迟，代价是不可靠。

## 3. 它解决什么问题

1. **极简低延迟**：无建连/拆连/确认开销，单请求-单响应（如 DNS）最快。
2. **保留消息边界**：每 datagram 独立，应用一次 recv 正好一条，天然"不粘包"。
3. **适合容忍丢包的场景**：实时音视频丢一帧不影响整体，重传反而添乱。
4. **广播/组播友好**：无连接使其天然支持一对多。

## 4. 核心特征

- **固定 8 字节头部**：源端口/目的端口各 2 字节、长度 2 字节、校验和 2 字节，极致精简。
- **无连接、不可靠**：不保证到达、有序、不重复；无流量/拥塞控制。
- **消息边界**：与 TCP 字节流相反，datagram 是最小交付单位。
- **校验和可选**：IPv4 下校验和可置 0（不计算）；IPv6 下必填。
- **最大载荷**：理论 **65507** 字节（65535−20IP−8UDP），超 MTU 由 IP 层分片（推荐应用层自切片）。

## 5. 与其他协议的关系

| 相关协议 | 关系 |
|---------|------|
| **TCP** | 同层替代：可靠有序但重；UDP 不可靠但轻快 |
| **QUIC** | 在 UDP 之上自建可靠+拥塞控制+加密，即 HTTP/3 传输 |
| **IP** | UDP 的承载（协议号 17） |
| **DNS/DHCP** | 典型 UDP 应用，靠自身重试保证关键交互 |
