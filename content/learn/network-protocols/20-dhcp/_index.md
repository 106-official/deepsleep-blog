## 1. 协议定位

| 项目 | 信息 |
|------|------|
| 所属层 | 应用层（Application Layer），但服务对象是网络层配置 |
| 英文全称 | Dynamic Host Configuration Protocol（动态主机配置协议） |
| 主要 RFC | **RFC 2131**（DHCP 协议）、**RFC 2132**（DHCP 选项与 BOOTP 厂商扩展）；RFC 3046（中继代理 Option 82）；RFC 1542（BOOTP 中继）；RFC 8415（DHCPv6）；RFC 3927（APIPA / 链路本地地址） |
| 端口 | **UDP 67**（服务端 / 中继监听）、**UDP 68**（客户端监听） |
| 封装于 | UDP → IP → 以太网；初始阶段客户端**无 IP**，故用 `0.0.0.0 → 255.255.255.255` 广播 |
| 典型应用 | 办公/家庭网络自动上网、Wi-Fi 接入、虚拟机与云主机初始化、PXE 网络启动 |

## 2. 一句话理解

**DHCP 是网络的"前台接待"：新设备一进门就广播喊"谁能给我个地址"，服务器登记后发一张有期限的门牌（租约），到期前要主动续期，走的时候可以交还。**

## 3. 它解决什么问题

手工为每台设备配置 IP、掩码、网关、DNS，在规模稍大的网络里立刻崩溃：容易输错、容易地址冲突、设备移动就要重配、地址回收全靠人记。DHCP 解决了四件事：

1. **自动分配地址**：从地址池中挑一个未被占用的地址下发，避免人工冲突。
2. **一次下发全套参数**：不只是 IP，还包括子网掩码、默认网关、DNS 服务器、域名后缀、NTP 服务器、TFTP/PXE 引导文件等（都通过 Option 携带）。
3. **租约回收复用**：地址是"租"的不是"送"的，设备离线后租约到期即可回收给别人，地址利用率大幅提升。
4. **跨网段服务**：DHCP 报文本是广播不能跨路由，中继代理（Relay Agent）把它单播转发给中心服务器，从而实现全网集中管理。

## 4. 核心特征

- **DORA 四步**：Discover（发现）→ Offer（提供）→ Request（请求）→ Ack（确认）。
- **基于广播 + UDP**：客户端此时还没有 IP，只能用源 `0.0.0.0`、目的 `255.255.255.255` 广播；用 `xid`（事务 ID）和 `chaddr`（MAC）来区分是不是发给自己的。
- **租约（Lease）机制**：地址有有效期，客户端在 **T1（50% 租期）**开始续租，**T2（87.5% 租期）**开始广播重绑定，到期未续则释放。
- **服务端无状态到有状态**：服务器需要维护"地址 ↔ MAC ↔ 到期时间"的租约数据库，这也是排查地址冲突的核心依据。
- **兼容 BOOTP**：DHCP 复用 BOOTP 的报文格式，靠 **Magic Cookie（99.130.83.99）** 与 Option 53 区分类型。
- **无认证**：报文明文且无身份校验，因此存在**私接 DHCP 服务器（Rogue DHCP）**与地址耗尽攻击，需要交换机 DHCP Snooping 防护。

## 5. 与其他协议的关系

| 相关协议 | 关系 |
|---------|------|
| **UDP** | 承载层；选 UDP 是因为无连接、支持广播、开销小 |
| **IP / 以太网** | DHCP 配置的正是 IP 层参数；报文以以太网广播帧发出 |
| **ARP** | 双向配合：服务器分配前可用 ICMP/ARP 探测地址是否被占用；客户端拿到地址后发 **ARP Probe / 免费 ARP** 检测冲突，冲突则发 `DHCPDECLINE` |
| **DNS** | DHCP 通过 Option 6 下发 DNS 服务器、Option 15 下发域名后缀；DDNS（RFC 2136）可让 DHCP 自动注册主机记录 |
| **BOOTP** | DHCP 的前身，报文格式相同；DHCP 是其超集 |
| **TFTP / PXE** | Option 66/67（或 `siaddr`/`file` 字段）下发引导服务器与引导文件，实现网络装机 |
| **DHCPv6**（RFC 8415） | IPv6 版本，端口改为 **UDP 546（客户端）/547（服务端）**，用组播 `ff02::1:2` 而非广播 |
