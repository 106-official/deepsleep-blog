## 先建立直觉

把安全想成**守一座城**：

- **城墙、护城河、哨塔**是防御手段；
- **粮仓、兵械库、城门**是你必须保护的**资产**；
- **敌军、间谍、内鬼**是**威胁**；
- **城墙的裂缝、无人看守的狗洞**是**漏洞**；
- **敌人从裂缝摸进来抢走粮草**就是一次成功的**风险事件**。

安全的目标不是"修一座打不破的城"（不可能），而是**让攻击成本高于攻击收益**，把风险降到可接受范围内。

## 它解决什么问题

很多"安全事故"的根因不是技术差，而是**没想清楚要保护什么**：

- 把数据库暴露在公网还怪"黑客太强"——其实缺的是"资产分级"这一步；
- 上线才发现支付接口能被重放——缺的是"威胁建模"这一步。

本章给你的，是一套**在写第一行代码前就能用的思考框架**。

## 核心概念

### 1. CIA 三要素（安全的三个目标）

| 目标 | 英文 | 含义 | 反面（被破坏时） |
|------|------|------|------------------|
| 保密性 | Confidentiality | 只有该看的人能看 | 泄露（明文密码被拖库） |
| 完整性 | Integrity | 数据没被篡改 | 篡改（转账金额被改） |
| 可用性 | Availability | 该用时能用 | 拒绝服务（DDoS 打挂） |

> 安全和"体验/成本"常冲突。例如为了保密性强制 16 位复杂密码，可用性就下降。安全是**权衡**，不是"越严越好"。

### 2. 资产 / 威胁 / 漏洞 / 风险

```
风险 = 威胁 × 漏洞 × 资产价值
```

- **资产**：数据、系统、声誉（如用户手机号、源码、支付通道）。
- **威胁**：可能造成伤害的来源（外部黑客、内鬼、自然灾害）。
- **漏洞**：资产自身的弱点（未鉴权接口、弱密码、未打补丁）。
- **风险**：上述三者结合后"真的发生坏事"的可能性与影响。

### 3. 攻击者视角的两条主线

**网络杀伤链（Kill Chain）**——一次入侵的典型阶段：

```mermaid
flowchart LR
    A[侦察 Recon] --> B[武器化 Weaponize]
    B --> C[投送 Delivery]
    C --> D[利用 Exploit]
    D --> E[安装 Install]
    E --> F[指挥控制 C2]
    F --> G[行动达成目标]
```

**MITRE ATT&CK** 是更细的战术/技术矩阵（如 T1566 钓鱼、T1059 命令与脚本解释器），常用于**检测规则编写**和**红蓝对抗**的对齐。

### 4. 威胁建模：STRIDE

在系统设计阶段，对每个组件问六个问题（STRIDE）：

| 字母 | 威胁类型 | 对应 CIA | 典型问法 |
|------|----------|----------|----------|
| S | 仿冒 Spoofing | 保密/完整 | 谁能假装别人？ |
| T | 篡改 Tampering | 完整 | 数据能被改吗？ |
| R | 抵赖 Repudiation | 完整 | 操作能被否认吗？ |
| I | 信息泄露 Information Disclosure | 保密 | 秘密会漏吗？ |
| D | 拒绝服务 Denial of Service | 可用 | 能让它瘫吗？ |
| E | 提权 Elevation | 完整/授权 | 能拿到更高权限吗？ |

### 5. 纵深防御（Defense in Depth）

不要只依赖一道墙。每层都失效一点，但叠加后整体安全：

```
边界防火墙 → WAF → 应用鉴权 → 参数校验 → 数据库最小权限 → 审计日志
```

## 常见坑

1. **只买设备不建流程**：防火墙、IDS 买了一堆，却没有人看告警、没补丁机制，等于城墙建好没人巡逻。
2. **把"合规"当"安全"**：过了等保/ISO 不代表不会被黑，合规是底线不是终点。
3. **忽视内部威胁**：80% 的真实损失里常有内鬼或误操作的影子，权限要最小化和可审计。
4. **追求"绝对安全"**：资源错配。优先级应是"先堵住能拖库、能转账的高危漏洞"。
5. **没有应急响应预案**：出事后才发现备份不可用、没人有权限关机器——演练比设备更重要。

## 小结

- 安全的本质是**风险管理**：`风险 = 威胁 × 漏洞 × 资产价值`；
- 用 **CIA** 描述目标，用 **STRIDE** 在设计中找威胁，用 **Kill Chain / ATT&CK** 理解对手；
- 落地靠**纵深防御**，把"单点失效"变成"层层削减"；
- 下一章进入 Web 安全：先搞懂 HTTP/HTTPS 与会话机制，那是后续所有 Web 漏洞的"舞台"。
