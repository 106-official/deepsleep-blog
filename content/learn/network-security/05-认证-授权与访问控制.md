## 先建立直觉

- **认证（Authentication）**："你是谁？"——登录、刷脸、令牌；
- **授权（Authorization）**："你能做什么？"——普通用户不能删全站、不能看别人账单。

很多事故出在把两者混为一谈：**认证通过了，但授权没拦住**。一个登录用户改一下 URL 里的 `id`，就读到了别人的订单——这是**越权**，和"密码破没破"无关。

## 核心概念

### 1. 认证：密码怎么存才安全

```mermaid
flowchart LR
    A[明文密码] -->|直接存| B[拖库即全裸 ❌]
    C[MD5(密码)] -->|无盐, 彩虹表秒破 ❌| D[危险]
    E[bcrypt/argon2(密码+随机盐)] -->|慢哈希+盐| F[即使泄露也难破 ✅]
```

**铁律**：
- 永远**不存明文**，不用 MD5/SHA1 裸哈希；
- 用 **bcrypt / scrypt / Argon2** 等"慢哈希" + 每用户随机盐；
- 登录失败做**限流 + 渐进延迟**，挡暴力破解。

```js
const bcrypt = require('bcrypt');
const hash = await bcrypt.hash(password, 12);          // 注册/改密时
const ok   = await bcrypt.compare(password, hash);     // 登录校验
```

### 2. 会话 vs JWT

| 机制 | 状态 | 撤销 | 适用 |
|------|------|------|------|
| Session + Cookie | 服务端存状态 | 易（删 session） | 传统 Web、需强管控 |
| JWT | 无状态（自带声明） | 难（要短过期+黑名单） | 微服务/跨域 |

**JWT 常见误用**：
- **密钥弱 / 用 `none` 算法**：攻击者可伪造任意声明（`{ "role":"admin" }`）；
- **把敏感数据塞进 payload**：JWT 只是 Base64，谁都能解码读；
- **不过期或过期太长**：丢了难追回，应短 `exp` + 刷新令牌。

### 3. OAuth2 典型陷阱

OAuth2 是"授权第三方访问"，不是"认证协议"（OpenID Connect 才是认证）。常见坑：
- **`redirect_uri` 未严格校验**：跳板到攻击者域名，授权码被截；
- **把 access_token 当身份认证**：应校验 `id_token` / 用户信息接口；
- **隐式流（implicit）把 token 放 URL**：已被弃用，用 PKCE 授权码流。

### 4. 越权漏洞（重点）

**水平越权（IDOR）**：A 用户访问到 B 用户的数据。

```
GET /api/order/1001    改 1002 → 看到别人订单
```

**垂直越权**：普通用户调到管理员接口。

```
POST /api/admin/deleteUser    普通用户竟能成功
```

**根因**：服务端只信了"前端没显示这个按钮"，没在**每个接口**校验"当前用户对此资源是否有权"。

## 防御：防越权的标准动作

```js
// 每个涉及资源的接口都做"所有权 + 角色"双重校验
app.delete('/api/order/:id', auth, async (req, res) => {
  const order = await Order.findById(req.params.id);
  if (!order) return res.status(404).end();
  if (order.userId !== req.user.id && req.user.role !== 'admin')
    return res.status(403).end();          // ✅ 越权拦截
  await order.destroy();
  res.end();
});
```

配合：**基于角色的访问控制（RBAC）**、**默认拒绝**（没显式允许就拒绝）、**对象级鉴权框架**（如 OWASP 推荐的全局过滤器）。

## 常见坑

1. **前端隐藏按钮 = 权限控制**：攻击者直接用 curl 调接口，前端"看不见"没用。
2. **JWT 用 `none` 或弱密钥**：可被重放/伪造，务必强随机密钥 + 校验算法白名单。
3. **Session ID 放 URL**：会进日志、Referer、浏览器历史，泄露即失陷。
4. **改密不校验原密码**：别人拿到已登录设备直接改密窃取账号。
5. **ID 连续可枚举 + 无归属校验**：典型的 IDOR，订单/发票/私信重灾区。

## 小结

- **认证管身份，授权管边界**，两边都要做；
- 密码用 **慢哈希 + 盐**，JWT 必须**强密钥 + 短过期 + 算法白名单**；
- **越权是高频事故源**：每个接口都要校验"当前用户对该资源是否有权"，不能只靠前端；
