## 先建立直觉

前面 8 章是"知识点"，这一章把它们**串成一次完整的防御验证**：像攻击者一样去思考，但目的是**发现并修复自己系统的弱点**。这就是安全测试（渗透测试 / 红队）的价值。

> 再次强调：**只在你拥有或明确授权的目标上做**。渗透测试的核心不是"技术多狠"，而是"**有授权、有范围、有报告、有修复**"。

## 核心概念

### 1. 方法论：PTES 七阶段

```mermaid
flowchart TD
    A[前期交互: 明确范围/授权/目标] --> B[情报收集: 资产/子域/端口]
    B --> C[威胁建模: 哪类攻击最致命]
    C --> D[漏洞分析: 扫描+人工确认]
    D --> E[渗透利用: 验证可利用性]
    E --> F[后渗透: 影响评估(不外扩)]
    F --> G[报告: 风险+复现+修复建议]
```

每一步都要**留痕可审计**，且严格不超出约定的授权边界（不动生产数据、不造成破坏）。

### 2. Burp Suite：Web 测试的"显微镜"

常见用法（Community 版够用）：

- **Proxy 拦截**：看每个请求/响应，改参数重放；
- **Repeater**：把请求钉住反复改、对比响应；
- **Intruder**：对参数做字典爆破（仅授权目标）；
- **Decoder**：编解码（URL/Base64/HTML），分析混淆 payload。

实战示例：在 DVWA 把评论参数改成 `<script>alert(1)</script>` 重放，确认是否触发 XSS（对应第 3 章）。

### 3. Wireshark：流量层的"听诊器"

- 过滤式：`http.request`, `tcp.port == 443`, `dns`, `ip.addr == 1.2.3.4`；
- 看明文协议（HTTP/FTP/Telnet）里的密码——直观说明"为什么必须 HTTPS"；
- 看 TCP 三次握手、TLS 握手（对应第 6 章）。

### 4. 靶场与 CTF（合法练习）

| 环境 | 用途 |
|------|------|
| DVWA / WebGoat / sqli-labs | 单点漏洞练习（XSS/注入） |
| OWASP Juice Shop | 现代 Web 综合漏洞 |
| TryHackMe / Hack The Box | 系统化授权实战（需账号） |
| CTFtime 赛事 | 限时综合挑战 |

### 5. 红蓝对抗

- **红队**：模拟真实攻击者，测"能不能进来、进来后能到哪"；
- **蓝队**：防守方，看检测与响应是否生效；
- 价值在于**用对抗检验体系**，而非单次扫描。

## 动手：第一次合法测试

1. 本地 `docker run -p 8080:80 vulnerables/web-dvwa` 起靶场；
2. Burp 挂代理，浏览器走 8080；
3. 在"SQL Injection"用 `' OR '1'='1` 验证注入，再切"Impossible"看源码如何用预编译挡；
4. 写一份**最小报告**：漏洞位置、复现步骤、风险等级、修复建议。

## 常见坑

1. **无书面授权就开扫**：即使是"测试自己公司"，也要范围与书面许可，避免合规风险。
2. **只扫不验证**：扫描器报"高危"但人工未确认，可能是误报，报告要可信。
3. **在靶场用真实数据**：练习环境请用水桶数据，别把生产用户导入靶场。
4. **重利用轻报告**：找不到漏洞也要交付"测了什么、为何安全"的结论，否则测试无意义。
5. **越界外扩**：授权只到某 IP，却顺手扫了隔壁网段——违反授权即违法。

## 小结

- 安全测试 = **有授权、有范围、有方法（PTES）、有报告**的防御验证；
- 工具：Burp 看 Web、Wireshark 看流量、靶场/CTF 练手；
- 红蓝对抗用真实对抗检验整个安全体系；
- 下一章：把"单次测试"升级为"常态安全运营"——日志、IDS/IPS、等保与应急响应。
