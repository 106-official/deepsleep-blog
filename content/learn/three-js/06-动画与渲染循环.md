## 先建立直觉

3D 动画的本质就是**每秒把场景重新画 60 次**，每次画之前稍微改一点点（转 0.01 弧度、移 0.1 单位）。人眼把这 60 张连起来，就成了"动"。

所以"做动画"= "在渲染循环里，每帧根据时间改物体的属性"。

## 它解决什么问题

新手常犯两个错：用 `setInterval` 驱动渲染（和屏幕刷新不同步，掉帧/撕裂/费电），或每帧无脑 `+0.01`（高刷屏上快得飞起）。正确的做法是用 `requestAnimationFrame` 跟随屏幕刷新，并用 **时间差（delta）** 让动画速度与帧率无关。

## 核心概念

### 1. 渲染循环：用 rAF，不用 setInterval

```js
function animate() {
  requestAnimationFrame(animate); // 浏览器在下一次重绘前回调，通常 60fps
  renderer.render(scene, camera);
}
animate();
```

> `setInterval(render, 16)` 看起来也动，但：① 不与显示器垂直同步，会撕裂；② 后台标签页仍跑，浪费电；③ 高刷屏（120/144Hz）它被锁死在 ~60。`rAF` 免费解决这三点。

### 2. Clock：拿"这一帧过了多久"

```js
const clock = new THREE.Clock();

function animate() {
  requestAnimationFrame(animate);
  const dt = clock.getDelta();        // 距上一帧的秒数（如 0.016）
  const t = clock.getElapsedTime();   // 累计秒数

  cube.rotation.y += dt * 1.0;        // 每秒转 1 弧度，60/144Hz 速度一致
  cube.position.y = Math.sin(t * 2) * 0.5; // 用累计时间做正弦浮动
  renderer.render(scene, camera);
}
```

| API | 返回 | 用途 |
|------|------|------|
| `getDelta()` | 距上一帧秒数 | 让位移/旋转"每秒 X"，帧率无关 |
| `getElapsedTime()` | 累计秒数 | 做周期性运动（sin/cos）、时间轴 |

> **帧率无关心法**：凡是"每帧动多少"，都乘 `dt`。否则 144Hz 屏上动画会比 60Hz 快 2.4 倍。

### 3. 缓动与插值（让运动不生硬）

```js
// 线性插值：从 a 向 b 靠近，alpha 越大越快
cube.position.x = THREE.MathUtils.lerp(cube.position.x, targetX, 0.1);

// 数值映射 + 缓动函数
const k = THREE.MathUtils.clamp(t, 0, 1);
const eased = k * k * (3 - 2 * k); // smoothstep 缓入缓出
```

常用缓动（可直接抄）：
- `smoothstep`: `k*k*(3-2k)` 缓入缓出
- `easeOut`: `1-(1-k)*(1-k)`
- `easeInOut`: `k<0.5 ? 2k*k : 1-(-2k+2)^2/2`

### 4. 物体自身的动画系统（AnimationMixer）

加载 GLTF 模型后，模型自带骨骼动画，用 `AnimationMixer` 播放（见第 7 章）：

```js
const mixer = new THREE.AnimationMixer(model);
const action = mixer.clipAction(gltf.animations[0]);
action.play();
// 循环里：mixer.update(dt);
```

## 动手写：用时间驱动的复合动画

```js
const clock = new THREE.Clock();

function animate() {
  requestAnimationFrame(animate);
  const dt = clock.getDelta();
  const t = clock.getElapsedTime();

  cube.rotation.y += dt * 0.8;                       // 匀速自转（帧率无关）
  cube.position.y = Math.sin(t * 1.5) * 0.4;          // 上下浮动
  cube.scale.setScalar(1 + Math.sin(t * 3) * 0.05);   // 轻微呼吸缩放
  controls.update();
  renderer.render(scene, camera);
}
animate();
```

## 常见坑

1. **高刷屏上动画飞快**：每帧写死 `+0.01` 没乘 `dt`。改 `+= dt * 速度`。
2. **用 setInterval 驱动渲染**：换成 `requestAnimationFrame` 循环。
3. **循环里 `getDelta` 调两次**：`getDelta()` 每次调用都会重置计时，一帧只能取一次，存到变量再用。
4. **动画卡顿/掉帧**：瓶颈通常在几何体/着色，不在循环本身；先用 `stats.js` 看帧率再优化（第 8 章）。
5. **模型动画不动**：`mixer.update(dt)` 必须在循环里调用，且 `action.play()` 过。

## 小结

- 动画 = 渲染循环里每帧改属性；用 `requestAnimationFrame` 而非 `setInterval`；
- 用 `Clock.getDelta()` 让速度与帧率无关，避免高刷屏加速；
- 平滑运动用 `MathUtils.lerp` + 缓动函数；
- 模型骨骼动画交给 `AnimationMixer`；
