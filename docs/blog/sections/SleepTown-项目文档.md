## 项目概述

**SleepTown** 是一款基于浏览器的社交推理游戏，灵感来源于经典的"狼人杀"和"Among Us"等游戏。玩家扮演一个鱼塘的管理者，需要通过"问询"机制找出隐藏在鱼群中的坏鱼，保护豪鱼们的安全。

### 当前版本特色 (v3.7.0 游戏逻辑 · Noir 视觉 v3.8)

- **双模式系统**: 自由模式（自定义配置）+ 关卡模式（固定挑战）
- **关卡模式 sidebar 布局**: learn 风格「左固定章节列表 + 右关卡详情卡片」，移动端抽屉化 (v2.2.2.0)
- **十二种角色系统**: 豪鱼阵营(6种) + 坏鱼阵营(2种) + 中立阵营(4种，含法师D)
- **多样化线索**: 侦探D、法官D、八卦鱼、梦游D各有独特信息提供方式
- **智能伪装**: 所有坏鱼都会伪装成当前游戏中存在的角色
- **13个关卡挑战**: 第1章8关 + 第2章3关 + 第3章2关，支持连续挑战
- **灵活配置**: 支持 6-20 只鱼，自定义角色种类
- **跳过机制**: 可跳过问询或流放阶段
- **首登场角色机制弹窗 (v3.4.0)**: 进入某关时，若该关首次出现某角色，自动弹出 Noir 风格简报，介绍其游戏机制
- **玩法提示与应对策略 (v3.4.1)**: 简报与角色档案新增"玩法 / 应对"一行，由 `FISH_ROLES[role].tip` 中央数据驱动，给出该角色的实战建议与反制思路；角色参考表同步补全至十二种角色
- **风灯 3D 开场闪屏 (v3.5.0)**: 进 `/play/sleeptown/` 即播约 4.5 秒电影感开场——中央一盏发光风灯（自身即 PointLight 光源）+ 低面粒子上浮 + 细致低面鱼影（纺锤鱼身/分叉尾鳍/背腹胸鳍/发光金眼，尾鳍摆动）环绕旋转；鼠标移动触发相机视差与灯光偏移（移动端自动旋转）。Three.js r160 自托管于 `static/js/three.module.min.js`（无第三方 CDN 依赖），无 WebGL 时降级纯 CSS 风灯呼吸灯。右上「跳过 ✕」、右下「进入 →」随时淡出进首页；每次加载都播，带「不再自动播放」开关（localStorage，默认关）
- **暗房显影动效层 (v3.6.0)**: 以「暗房显影」为统一母题——所有揭示都像照片在显影液里从模糊/低对比慢慢浮现，金边由 0 渐显。**关卡选择**：章节列表逐项金线入场（选中态金线绘制）+ 右侧详情卡暗房显影 + 金边浮现 + 点击「开始挑战」进入对局时面板同步显影过渡。**问询**：点鱼卡触发金色光扫 + 轻微下沉；鱼卡揭示时暗房显影；线索逐条墨迹浮现（同批日志自动错峰 ~120ms）；印章「盖下顿挫」（scale 1.4→1 带回落）；日志流统一曲线。全程纯 CSS + 少量 CSS 变量 stagger，零新依赖、不碰 Three.js；新增 `--st-ease` 统一缓动，并整体包在 `prefers-reduced-motion: no-preference` 内（尊重减弱动效偏好）
- **开场时序修复 + 三处过渡画面 (v3.7.0)**: 修复「点进页面先弹关卡选择再弹开场闪屏」的时序 bug——`#splash` 首帧即不透明全覆盖，关闭逻辑（`window.__dismissSplash`）移至非延迟脚本，Three.js 模块加载慢/失败也能随时「跳过 / 进入 / 不再自动播放」，首页与关卡选择不再先于开场闪现。新增三处全屏过渡画面，统一沿用「暗房显影」母题（复用 `stDevelop` / `stGoldRing` / `stStamp` 关键帧，`--st-ease` 缓动，包在 `prefers-reduced-motion` 内）：① **进入关卡**——「案卷暗房显影」覆盖层（关卡号 + 案名 + "调查开始"），约 760ms 后揭示对局面板；② **游戏胜利**——「结案」绿印（`--st-good`）盖下 + 绿色光晕扩散；③ **游戏失败**——「失守」红印（`--st-stamp`）盖下 + 红色光晕扩散。零新依赖
- **Noir 动效增强与材质精致化 (v3.8.0)**: 经 `/grill-me` 6 问对齐（全选「揭示+转场 / 材质真实感 / 更鲜明 / 放逐裁决为英雄时刻 / 统一 :root 令牌 / 1:1 reduced-motion」）→ ① **放逐裁决**：径向聚光（`.exile-beam`）+ 打字机逐字宣判，由 `showExileVerdict()` 驱动（`exileFish()` 改调它播「N 号·角色名（阵营）」）；② **墨晕转场** `stInkTransition(showId,hideId)`：全屏墨晕遮罩 + `#st-inkbleed`（feTurbulence+feDisplacementMap 墨晕滤镜）+ 斜向擦除，6 个切换函数（showFreeModeSetup / showStageMode / backToModeSelection / goBackToSetup / startFreeModeGame / quickStart）统一走它，并修复原 mask 遮罩导致进入关卡模式后黑屏的回归 bug；③ **真相网格揭示** `.truth-item.reveal-st`（`truthReveal` 模糊入 + `--i` 错峰）。Phase 3 精致化新增 `:root` 令牌（`--st-ease-soft`/`--st-ease-ink`、`--st-dur-s/m/l`、`--st-stagger`、颗粒 `--st-grain` feTurbulence data-URI），放逐裁决加体积光+微呼吸+尘埃+颗粒、墨晕更厚、真相网格错峰 token 化，并 1:1 落实 `prefers-reduced-motion` 降级。配套参考集 `docs/SleepTown-动效参考集.md` + 自包含 demo `docs/SleepTown-动效demo.html`

## 🎨 视觉系统：Noir 深夜渔港侦探档案 (v3.1)

> 设计方向确认于 2026-08-02（`docs/superpowers/specs/2026-08-02-sleeptown-noir-design.md`），2026-08-03 完成整块重构与"去 AI 味"打磨。与 CardArena 的苏丹宫廷黑金（暖色奢华）刻意区分：SleepTown = 深夜渔港 × 墨蓝灯塔 × 侦探档案（冷色克制）。

### 艺术逻辑
游戏机制天然契合**黑色电影（Film Noir）侦探档案**美学：问询=审讯、流放=定罪、夜晚=凶案、伪装=伪造档案。参考黑色电影海报的高对比光、老式侦探档案的牛皮纸/打字机/红色印章、灯塔与深海的暖冷对峙。

### 设计系统（单一调色板 `--st-*`）
- **暗色 Noir 墨夜蓝**：`--st-bg #0b1320` / `--st-surface #16233a` / `--st-ink #d8c49a`（档案纸色）/ `--st-lamp #e8c87a`（灯塔暖灯）/ `--st-stamp #c0392b`（定罪红印）
- **亮色 档案室白天**：牛皮纸 `#f2e8d0` 系 + 黄铜 `#a06a1f`
- **阵营色**：`--st-good #8fd0a8` / `--st-bad #e0655a` / `--st-neutral #c3b1a6`
- 全部变量在 `:root` 与 `[data-theme="dark"]` 双主题定义；**无任何脱色调硬编码**（原 v2.x 的 `#667eea` 蓝紫 / `#27ae60` 绿 / `#f39c12` 橙渐变已全部清除）。

### 字体层级
- 标题/按钮：`Playfair Display` 衬线 + `letter-spacing`
- 日志/编号/印章/英文装饰：`Courier New` 打字机体
- 正文：系统无衬线

### 核心组件规范
- **鱼卡档案**：双虚线内框 + 旋转橡胶印章（已定罪 / 已牺牲 / 已结案 / 待取证）+ 角色 SVG 徽记（10 枚线稿，随阵营着色）+ 阵营标签；悬停上浮、揭示时墨迹晕开。
- **按钮（三态黄铜铭牌）**：surface 渐变 + 强边框 + 3px 底部厚边（物理感），hover 上浮、active 压边；主行动=黄铜金、流放/定罪=定罪红、普通=档案灰。彻底摒弃"扁平渐变圆角卡片"的 AI 默认按钮味。
- **状态栏**：独立档案卡小组件，左竖线灯塔色，typewriter 大写标签（PHASE / INQUIRIES / ALIVE）。
- **日志**：牛皮纸面板 + 左侧暖灯竖线 + `[HH:MM]` 时间戳 + Noir 色板；新日志墨迹晕开入场。
- **弹窗/结果**：surface 渐变 + 顶部金线；胜利=绿印边、失败=红印边；结果按钮统一黄铜。
- **页面背景**：灯塔径向光晕（右上）+ 墨蓝垂直渐变；游戏主面板额外叠加**黑色电影暗角（vignette）**，强化戏剧灯光。

### 去 AI 味打磨（2026-08-03 迭代）
- 整块 CSS 重写为**单一无冲突系统**（移除 v3.0 时期并存的旧块与覆盖层）。
- 导航 / 配置角色勾选 / 角色详情 / 规则卡 的 emoji 全部替换为 **SVG 线稿徽记**（复用 `getRoleAvatar()`）；侧栏分组图标改为单色符号（▷ ≈ ◈ ✕ ¶）。
- 所有"开始 / 再来一局"等主按钮统一黄铜，清除通用成功绿渐变。
- 文案 Noir 化：首页副标题 `CASE FILE №2 · 深海渔港十角色`、提示 `← 侧栏点名，调阅角色档案`、版本标注 `深夜渔港 Noir`。

### 动效克制原则
所有微交互过渡 ≤0.3s，悬停仅上浮 2px，入场用墨迹/模糊晕开，不做弹性/缩放炫技——符合"严苛克制"的 Noir 气质。v3.6.0 起「暗房显影」揭示层（详情卡 / 鱼卡 / 线索 / 印章）单元素时长放宽至 ≤600ms，但母题统一、曲线收敛（新增 `--st-ease`），不引入霓虹/流光，仍属克制范围。v3.7.0 新增三处全屏过渡画面（进入关卡「案卷暗房显影」、胜利「结案」绿印光晕、失败「失守」红印光晕），沿用同一母题与 `--st-ease`，单元素 ≤950ms，仍属克制范围。v3.8.0 在保持克制的前提下引入「材质真实感」以强化电影感：颗粒（feTurbulence 噪声，`mix-blend-mode:soft-light`）、体积光、尘埃、墨迹拖影——皆服务于氛围而非炫技；新增统一令牌 `--st-ease-soft` / `--st-ease-ink` / `--st-dur-s/m/l` / `--st-stagger` / `--st-grain` 驱动节奏与质感。一个回归教训：`.ink-wipe` 曾用 `mask-size:260%` + `animation-fill-mode:both`，动画停在终态把屏幕左下半遮黑（进入关卡模式黑屏），已改为 opacity+blur 揭示。

## 角色系统详解（十二种角色）

### 阵营分类

| 阵营 | 胜利条件 | 数量占比 |
|------|---------|---------|
| **豪鱼阵营** | 所有坏鱼被淘汰 | ~60% |
| **坏鱼阵营** | 豪鱼数量 ≤ 坏鱼+中立 | ~25% |
| **中立阵营** | 存活至游戏结束 | ~15% |

### 完整角色列表

| 角色 | 阵营 | 机制 | 问询效果 | 玩法 / 应对 |
|------|------|------|---------|------------|
| **摆烂D** | 豪鱼 | 无特殊能力 | "什么也没发生" | 只是普通好鱼，白天优先采信侦探/法官线索，别凭直觉下刀 |
| **侦探D** | 豪鱼 | 揭示一条真实坏鱼的编号 | "#X 号是坏鱼！"（真实） | 好鱼方灯塔，记下指向号码并主动报点；出局前务必说清线索 |
| **法官D** | 豪鱼 | 揭示一条非豪鱼的编号 | "#X 号不是豪鱼！" | 与侦探的坏鱼编号取交集，可快速缩小凶手范围 |
| **八卦鱼** | 豪鱼 | 检查相邻鱼是否有非豪鱼 | "有瓜吃！" / "并没有瓜..." | 只看邻居，回报"有瓜吃"说明左右必有坏/中立，可往两侧推断 |
| **梦游D** | 豪鱼 | 提供3个号码，其中一只是坏鱼/中立 | "#X, #Y, #Z 中有一只不是豪鱼！" | 把三号码当嫌疑池，结合法官/侦探逐步排除 |
| **验尸官** | 豪鱼 | 翻开后随机揭示一只已死亡鱼的真实身份 | 尸检结果（揭示死者真身） | 优先验死得蹊跷者，常能翻出被伪装掩盖的真相；流放前验尸最值 |
| **邪恶D** | 坏鱼 | 夜晚杀人；被问询时完美伪装 | 显示为被伪装角色的效果 | 兼具击杀与伪装，白天混成无害好鱼，专挑侦探/法官下手；好鱼警惕"完美无害"者 |
| **殉道D** | 坏鱼 | 死亡后立即杀死一只好鱼；会伪装 | 同邪恶D，死亡时触发诅咒 | 流放前确认当晚谁会死、能否承受报复；必要时留到夜杀解决 |
| **法师D** | 中立 | 每晚令一只鱼特性失效，问询时告知影响谁 | 告知"昨晚令 #X 失效" | 搅局者，把失效用在虎鲸/邪恶D能救场，也能故意放开制造混沌 |
| **恶作剧D** | 中立 | 翻开后减少一次问询机会 | "问询机会减少1次！" | 翻开会拖慢好鱼节奏，好鱼若问询变少即疑身边有你；你则藏好别早暴露 |
| **虎鲸** | 中立 | 每晚随机杀死一条其他的鱼（不分阵营） | "今晚要小心了..." | 随机杀人制造人人自危；好鱼别把所有夜死者都算在邪恶D头上 |
| **幽灵** | 中立 | 翻开后当夜额外带走一条随机的鱼（不分阵营） | （无问询，夜间生效） | 一次性混乱，好鱼要意识到某夜可能多死一条别被误导；你趁乱脱身 |

### ⚠️ 伪装机制 (v2.1.1.2更新)

**重要规则**：
1. **所有坏鱼都会伪装**：邪恶D和殉道D被翻开时都会伪装
2. **智能伪装目标**：只伪装成**当前游戏中存在的角色**
3. **完美伪装效果**：
   - 显示的角色名称与真角色完全相同
   - 触发的效果也与被伪装的角色一致
   - **没有任何标记可以区分真假**
4. **揭示时机**：只有在游戏结束时才会揭示真相

**示例**：
```
场景：游戏中存在 [摆烂D, 侦探D, 法官D, 恶作剧D]

邪恶D被翻开 → 可能伪装成法官D
  → 显示："#X 号是 ⚖️法官D"
```

```javascript
// 计算各阵营总数
goodTotal = max(goodRoleTypes, floor(count * goodRatio))
evilTotal = max(evilRoleTypes, floor(count * evilRatio))
```

```javascript
function getNextStageId(currentStageId) {
```

### 详细操作说明

#### ☀️ 白天 - 问询阶段

**操作规则**：
1. 初始状态：所有鱼的身份隐藏（❓）
2. 每轮有 **N次问询机会**（默认3次，可配置）
3. 点击任意未翻开且存活的鱼进行问询
4. 问询后该鱼身份揭晓并触发对应效果

**各角色问询效果详情**：

| 角色 | 日志输出 | 特殊效果 |
|------|---------|---------|
| 摆烂D | `😴 #X 号是一条普通的摆烂D` | 无 |
| 侦探D | `✨ #X 号是 🔍侦探D！`<br>`🗣️ #X 号说：#Y 号是坏鱼！` | 提供真实坏鱼编号 |
| 法官D | `✨ #X 号是 ⚖️法官D！`<br>`⚖️ #X 号宣判：#Y 号不是豪鱼！` | 提供非豪鱼编号 |
| 八卦鱼 | `✨ #X 号是 📰八卦鱼！`<br>`📰 "有瓜吃！" 🍉` 或 `"并没有瓜..."` | 检查相邻位置 |
| 梦游D | `✨ #X 号是 💤梦游D！`<br>`💤 #X 号在梦中呓语：#A, #B, #C 中有一只不是豪鱼！` | 提供3个可疑号码 |
| 邪恶D | `⚠️ #X 号是 [伪装角色]...` | 伪装 + 触发伪装角色效果 |
| 殉道D | `⚠️ #X 号是 [伪装角色]...` | 伪装（死亡时触发诅咒） |
| 恶作剧D | `😐 #X 号是 🎭恶作剧D（中立）`<br>`🎭 触发恶作剧效果！**你的问询机会减少了1次！**` | 减少1次问询机会 |
| 虎鲸 | `🐋 #X 号发出低沉的鸣叫...今晚要小心了！` | 无即时效果（夜晚生效）|

**特殊机制**：
- **恶作剧D**：翻开后**减少1次**问询机会（v2.1.1.1修改，原为清空所有）
- **殉道D**：如果被流放或杀死，**立即杀死1只好鱼**作为报复
- **虎鲸**：每夜晚阶段额外随机杀1条鱼（不分阵营）

#### ⏭️ 跳过问询功能 (v2.1.1.2新增)

**激活条件**：
- 至少已使用过1次问询机会
- 仍有剩余问询次数未使用

**效果**：
- 立即结束问询阶段
- 剩余问询机会作废
- 解锁流放模式按钮

**适用场景**：
- 已获得足够信息，不想冒险继续问询
- 想尽快进入流放阶段

#### ⚖️ 流放阶段

**激活条件**：问询次数用完（包括提前跳过）

**操作方式**：点击任意未翻开且存活的鱼

**后果**：
- 被流放的鱼直接淘汰（alive=false）
- 真实身份揭晓给所有玩家
- 如果是**殉道D**，触发死亡诅咒效果

#### 🚫 跳过流放功能

**效果**：本轮不淘汰任何鱼，直接进入夜晚

**适用场景**：
- 信息不足，无法确定谁是坏鱼
- 避免误伤好鱼（特别是摆烂D较多的局面）
- 等待更多夜晚信息

#### 🌙 夜晚阶段

**执行顺序**：
1. **坏人行动**：所有存活的邪恶D和殉道D共同选择1只豪鱼击杀
2. **虎鲸行动**：存活的虎鲸随机选择1条其他鱼击杀（可能重复）
3. **结果公布**：第二天白天开始时显示所有受害者

**特殊情况**：
- 无存活坏鱼 → 夜晚平安无事
- 无存活好鱼 → 坏鱼胜利（游戏结束）
- 受害者可能同时被坏鱼和虎鲸选中

## 🏆 胜负判定

### ✅ 豪鱼胜利条件

满足以下任一条件即判胜：
1. **所有坏鱼都被淘汰**（通过流放或夜晚击杀）
2. 存活的豪鱼数量 > 0 且无任何坏鱼存活

### ❌ 失败条件

满足以下任一条件即判负：
1. **所有豪鱼都被消灭**（死亡或流放）
2. **豪鱼 + 中立阵营 ≤ 坏鱼阵营**

**失败弹窗显示**：

### ⚠️ 常见编程错误与解决方案

#### ❌ 错误1：关卡模式启动后显示"undefined"

**原因**：`initializeStageGame()` 创建新gameState时遗漏了 `currentStage` 属性

**错误代码**：
```javascript
gameState = {
  // ... 其他属性
  mode: 'stagemode',
  // ❌ 缺少 currentStage: gameState.currentStage,
  config: config
};
```

**正确代码**：
```javascript
gameState = {
  // ... 其他属性
  mode: 'stagemode',
  currentStage: gameState.currentStage,  // ✅ 必须保留
  config: config
};
```

#### ❌ 错误2：Hugo模板渲染问题

**症状**：页面显示空白或404

**可能原因**：
1. `content/play/sleeptown.md` 的 front matter 写错（例如误用 layout: sleeptown-freemode 等已删除的 Legacy 布局）
2. front matter中 `type` 和 `layout` 字段冲突
3. CSS语法错误导致模板解析失败

**解决方案**：
```yaml
---
title: "SleepTown 自由模式"
date: 2024-01-01
layout: sleeptown  # ✅ 仅保留layout字段
---
# 后面不要有任何HTML内容！
```

#### ❌ 错误3：CSS样式在 {{ end }} 之后

**错误结构**：
```html
{{ end }}
<style>
/* CSS代码 */
</style>
```

**正确结构**：
```html

/* CSS代码 */
</style>
{{ end }}
```

#### ❌ 错误4：按钮样式冲突

**症状**：关卡模式按钮悬浮时显示禁用样式
