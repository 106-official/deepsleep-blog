## 1. 项目概述

**定位**: DeepSleep 博客娱乐中心（`/play/`）新增的一款浏览器端回合制卡牌对战游戏，纯前端实现（无后端依赖），与 SleepTown 同属博客游戏板块。

**入口**: `https://deepsleep.fun/play/cardarena/`

**技术栈**: Hugo 布局模板 + 原生 JavaScript（ES6，模块化多文件）+ CSS 变量（跟随博客明暗主题）。

**玩法一句话**: 双方各选出 6 个角色轮流上场，每回合用当前角色的专属卡组出牌、召唤随从、发动攻击，一方 6 个角色全部阵亡即判负。

**与 SleepTown 的区别**: SleepTown 是单人推理；CardArena 是玩家 vs AI 的多角色轮换卡牌对战，且采用模块化多文件架构（为后续收藏/构筑扩展留空间）。

## 2. 核心玩法

### 2.1 对局流程

```
准备阶段 → 玩家从角色池选 6 个角色并排定出战顺序；AI 随机选 6 个
   ↓
每回合（轮流）：
  出战角色回合 → 出牌阶段（用该角色专属卡组 + 独立法力）→ 攻击阶段 → 结束回合
   ↓
角色血量归 0 → 自动换上出战顺序中下一个存活角色（被动换人，当回合剩余行动照常）
玩家可主动换人（消耗整个回合：不能出牌 + 不能攻击；新角色法力回满）
   ↓
一方 6 个角色全部血量归 0 → 该方判负，弹窗结算
```

### 2.2 回合内行动（玩家视角）

1. **出牌阶段**: 点击手牌打出（随从召唤上场 / 法术立即生效），费用不足则禁用。
2. **攻击阶段**: 点击出战角色或己方随从 → 再点击敌方目标（敌方随从或敌方出战角色）执行攻击。
3. **主动换人**: 消耗整个回合（本回合不能出牌也不能攻击），新角色上场且法力回满。
4. **结束回合**: 回合结束时当前角色法力回复 2 点（不超过上限），轮到对方行动。

## 3. 数据驱动设计（用户可自行配置）

游戏所有可配置内容集中在 `cardarena-data.js`，用户修改该文件即可自定义角色与卡牌，无需改动游戏逻辑。

### 3.1 全局配置

```javascript
const GAME_CONFIG = {
  handLimit: 5,       // 手牌上限
  manaMax: 5,         // 法力上限
  manaStart: 3,       // 首回合初始法力
  manaRegen: 2,       // 回合结束时回复法力
  minionLimit: 4,     // 每方场上随从上限
  startingHand: 3,    // 起手手牌数
  drawPerTurn: 1      // 每回合抽牌数
};
```

### 3.2 角色池（预设 8 个，玩家选 6，AI 随机 6）

```javascript
const ROLE_POOL = [
  {
    id: 'r1',
    name: '【角色名】',          // 用户自定义
    intro: '【一句话简介】',
    maxHealth: 20,              // 角色血量
    attack: 2,                  // 出战角色攻击力
    passive: {                  // 被动技能（每回合开始触发）
      name: '【被动名】',
      desc: '【效果说明】',
      type: 'heal', value: 1    // 效果类型（见 5.4，与卡牌 effect 同套 kind）
    },
    active: {                   // 主动技能（可选，P0 可先全部不配）
      name: '【主动技能名】',
      desc: '【效果说明】',
      type: '...',
      cost: 2                   // 消耗法力
    },
    deck: ['c1', 'c2', 'c3', 'c4', 'c5', 'c6']  // 专属卡组（引用 CARDS 的 id）
  }
  // ... 共 8 个角色
];
```

### 3.3 卡牌（随从 + 法术）

```javascript
const CARDS = [
  {
    id: 'c1',
    roleExclusive: 'r1',        // 专属卡：仅进入指定角色卡组；null 为通用卡
    name: '【卡名】',
    type: 'minion',             // minion 随从 / spell 法术
    cost: 2,
    attack: 2, health: 3,       // 仅随从
    keywords: ['taunt'],        // 关键词（见 5.2）
    effect: null,               // 法术/随从入场效果（见 5.4）
    desc: '【卡面文字说明】'
  }
  // ... 每角色 6-8 张（含 1-2 张专属特殊卡）
];
```

**约定**: 每个角色卡组 6-8 张，其中至少 1 张为专属特殊卡（`roleExclusive` 标记，仅该角色卡组可含）。P0 阶段全部 8 个角色卡组在数据文件中逐个配套预设，用户后续可自行增删。

## 4. 文件结构与模块职责

```
blog-static/
├── content/play/
│   └── cardarena.md            # front matter 声明 (layout: cardarena, url: /play/cardarena/)
├── layouts/_default/
│   └── cardarena.html          # 页面模板：HTML 骨架 + 引入 CSS/JS（无游戏逻辑）
├── static/css/
│   └── cardarena.css           # 游戏样式（极简几何风，--cardarena-* 变量定义在 :root）
└── static/js/
    ├── cardarena-data.js       # ⭐ 数据驱动层（GAME_CONFIG / ROLE_POOL / CARDS）
    ├── cardarena-engine.js     # 引擎：回合循环 / 出牌 / 战斗 / 关键词 / 换人 / 胜负
    ├── cardarena-ai.js         # AI 决策（依赖 engine 暴露的只读接口）
    └── cardarena-ui.js         # UI 渲染 + 点击交互 + 日志（依赖 engine + data）
```

**加载顺序（固定）**: `cardarena-data.js → cardarena-engine.js → cardarena-ai.js → cardarena-ui.js`。engine 依赖 data，ai/ui 依赖 engine。

**模块职责边界**:
- `data`: 纯数据，无逻辑。唯一被用户编辑的文件。
- `engine`: 游戏状态机与规则（不含 DOM 操作）。通过全局对象 `CardArena` 暴露 API（如 `CardArena.start()/playCard(id)/attack(from,to)/swapRole()/endTurn()`）。
- `ai`: 根据 engine 暴露的只读状态做决策，再调用 engine API。
- `ui`: 所有 DOM 操作，监听 engine 事件（自定义事件或回调）刷新界面。

**命名变更点**: 若游戏改名，涉及 `cardarena.html`、`cardarena.css`、4 个 `cardarena-*.js`、`content/play/cardarena.md`、`play.html` 新增卡片链接、`hugo.toml`（如需菜单）共 8 处。

## 5. 游戏引擎机制

### 5.1 回合循环（engine）

```
开始回合
  → 全局回合数 +1
  → 出战角色抽 1 张（手牌满则弃）
  → 被动技能触发
玩家阶段（出牌 → 攻击 → 换人 → 结束回合）
  → 回合结束：当前角色法力 +manaRegen（≤ manaMax）
  → 敌方 AI 阶段（同流程自动决策）
下一回合
```

**注**: 法力回复只发生在回合结束时（+2，不超过上限 5），回合开始沿用上一回合结束时的法力值；主动换人后新角色法力**回满**（= 上限）。

### 5.2 关键词系统（完整）

| 关键词 | 效果 |
|--------|------|
| `taunt` 嘲讽 | 对方攻击时必须优先攻击该随从 |
| `charge` 冲锋 | 召唤当回合即可攻击 |
| `deathrattle` 亡语 | 随从死亡时触发其 `effect` |
| `divine_shield` 圣盾 | 抵挡第一次受到的伤害（受到伤害后移除圣盾） |
| `poison` 剧毒 | 攻击或造成伤害后，被攻击/受伤害的随从直接死亡 |
| `windfury` 风怒 | 每回合可攻击两次 |

**随从基础规则**: 默认召唤失调（除冲锋外当回合不能攻击）；攻击可指向敌方随从或敌方出战角色；被攻击方受到等量攻击力伤害，血量归 0 即死亡（触发亡语）。

**出战角色攻击规则**: 出战角色有攻击力，可攻击敌方随从或敌方出战角色，伤害打在目标血量上；出战角色每回合可攻击一次（P0 简化，攻击后标记为已攻击，下回合重置）。

### 5.3 换人机制

| 类型 | 触发 | 后果 |
|------|------|------|
| 被动换人 | 当前角色血量归 0 | 自动换上出战顺序中下一个存活角色；当回合剩余行动照常 |
| 主动换人 | 玩家回合内点击"换人" | 消耗整个回合（不能出牌+不能攻击）；新角色法力回满 |

**限制**: 若所有候场角色均已死亡（仅剩当前角色存活），无法主动换人；当前角色阵亡时无存活候场角色 → 该方判负。

**随从归属**: 角色阵亡/换人时，其场上随从**保留**在战场，继续由该方操控（随从不随角色下场）。

### 5.4 效果类型（effect）

随从入场效果 / 亡语 / 法术 / 角色被动与主动技能统一使用类型化 `effect`（kind 枚举）：

| kind | 说明 | 参数 |
|------|------|------|
| `damage` | 对目标造成伤害 | `value` |
| `heal` | 治疗目标 | `value` |
| `draw` | 抽牌 | `value` |
| `buff` | 目标随从增益攻/血 | `attack`, `health` |
| `summon` | 召唤指定随从到己方战场 | `cardId` |
| `board_clear` | 清空对方所有随从（可选） | — |

### 5.5 胜负判定

- 任一角色血量 ≤ 0 → 触发被动换人；无存活角色可用 → 该方判负。
- 先手: 玩家；后手: AI（P0 无补偿抽牌）。

### 5.6 边界处理

- 牌库抽空 → 不再抽牌（P0 无疲劳伤害）。
- 手牌达到上限（5）→ 新抽的牌弃掉。
- 随从位满（4）→ 召唤类操作禁用。
- 法力不足 / 无合法攻击目标 → 对应卡牌/攻击按钮禁用。
- 所有目标均带嘲讽时 → 只能攻击嘲讽随从。

## 7. AI 策略（P0 基础）

- **出牌**: 有费用优先上随从（攻击力高的优先），法术优先用于解对方高威胁随从；无法力可施时跳过。
- **攻击**: 优先攻击对方低血量随从（解场），无随从可打时攻击对方出战角色。
- **换人**: 当前角色血量低于 30% 且本回合尚可行动时，主动换人。
- **实现方式**: 每回合 AI 阶段依次调用 `AI.decidePlay() → AI.decideAttack() → AI.decideSwap()`，每步通过 engine 只读接口获取状态，调用 engine API 执行。

## 8. UI/UX 设计（极简几何风）

### 8.1 布局

```
┌──────────────────────────────────────────────────┐
│ 顶部: 双方候场角色条（各 6 个血量格，出战角色高亮） │
├──────────────────────────────────────────────────┤
│ 敌方区: 敌方出战角色（血量/攻击/被动图标）          │
│         敌方战场（随从格子 ≤4，SVG几何图标+攻/血）  │
│ 中立:   对战日志（最新在最上）                      │
│ 我方区: 我方战场（随从格子 ≤4）                    │
│         我方出战角色（血量/攻击/被动/法力）          │
├──────────────────────────────────────────────────┤
│ 底部: 手牌区（≤5 张，点击出牌）                    │
│       操作栏: 换人 / 结束回合（扁平按钮）           │
└──────────────────────────────────────────────────┘
```

### 8.2 视觉约束（硬性）

- **无粗体文字**（font-weight 克制，不用 bold/strong）。
- **无 emoji**（全部图标使用内联 SVG 几何图形：圆/三角/方块区分随从/法术/角色）。
- **无卡片式按钮**（操作按钮为扁平样式，非卡片外观）。
- **极简几何风**: 冷色系为主，`--cardarena-*` CSS 变量定义在 `:root`，暗色模式用 `[data-theme="dark"]` 覆盖。
- 标题字体跟随博客 `Playfair Display, Georgia, serif`；正文 `Inter, sans-serif`。
- `.main:has(.cardarena-page)` 突破 PaperMod 768px 限制；移动端自适应堆叠（随从格 2 列）。
